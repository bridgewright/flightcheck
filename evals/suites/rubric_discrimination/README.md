# rubric_discrimination (evals layer 1)

Golden triplets test whether the content judge can tell BARS levels apart.
For each selected rubric dimension, one question gets three synthetic answers
(strong = score-5 behavior, borderline = 3, weak = 1) generated by OpenAI
(`[models].triplet_generator` in `services/scorer/config/product.toml`).
The judge (Gemini, via the product `score_content` path) must order them
strictly: strong > borderline > weak. Generator vendor != judge vendor to
block self-preference bias.

Rubrics used here come from representative **public** JDs only — never the
private application-target list (workspace rule R3).

## Layout

- `triplets/<dimension_key>-<n>.json` — TripletDoc: question + the three answers.
- `manual/<dimension_key>-<n>.yaml` — blind sheet: answers relabeled A/B/C in a
  seeded shuffle. Fill `ranking` (strongest -> weakest, e.g. `["C", "A", "B"]`)
  and `notes` by hand, without looking at the key.
- `manual/keys/<dimension_key>-<n>.yaml` — answer key (label -> variant). Kept in
  a separate file so the human ranker never sees the truth while ranking.

**Ranker warning:** rank from the `manual/` sheets only — both
`triplets/*.json` and `manual/keys/` contain the labeled ground truth, so
opening either before submitting your ranking voids the blind protocol.

## Commands (from `services/scorer/`)

- Generate: `uv run python -m scorer.evals_l1.golden generate --rubric <rubric.json>`
- Judge: `uv run python -m scorer.evals_l1.golden judge --rubric <rubric.json>`
  (writes `evals/out/rubric_discrimination.json`)

The human blind-rank on the manual sheets calibrates the judge: when human and
judge disagree on an ordering, trust the human and fix the rubric anchors or
the judge prompt before trusting the accuracy number.
