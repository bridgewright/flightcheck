## Layer 1 — rubric discrimination — `evals/out/rubric_discrimination.json`

```json
{
  "trials": 3,
  "correct": 3,
  "accuracy": 1.0,
  "failures": []
}
```

Suite: `evals/suites/rubric_discrimination/` (golden triplets from a
representative public JD; eval rubric at
`evals/suites/rubric_discrimination/rubric.json`). Human blind-rank agreed
with all three golden triplets before any judge run was trusted.

**Provenance — this 1.0 was not free.** The first measured run scored **0.0**
(the judge saturated strong and borderline at 5.0). Prompt-only iterations
plateaued at **0.33** (0.33 → 0.0 → 0.33). The judge was then redesigned —
one focused call per content dimension, anchor-first scoring rules, mean of
three seeded samples (commit `ddf6f92`) — and 1.0 is the stable result of
that reworked judge on **three consecutive runs**. The eval data, the metric,
and the 0.8 baseline were never touched during the iteration. Full story:
[RETRO.md](../../RETRO.md).

**Caveats:** N=3 triplets — a mechanism-level signal, not a large-sample
accuracy claim. The gate records per-variant scores only for failing trials,
so passing margins are not in the artifact (recording them is logged v0.2
work).

```json
{
  "triplets": 2,
  "dsp_pass": 2,
  "judge_pass": 2,
  "failures": []

```

Suite: `evals/suites/delivery_discrimination/` (controlled same-answer clip
triplets: fluent / filler / hesitant; clips gitignored per DECISIONS #005,
protocol in `clips/README.md`). Both checks passed on both triplets: DSP
separability (fluent strictly fewer silence events than hesitant) 2/2, and
judge ordering (fluent > hesitant, fluent > filler) 2/2 → judge accuracy 1.0
against the 0.8 baseline. DSP separability is recorded here but has no
committed baseline in v0.1 (not gated).
