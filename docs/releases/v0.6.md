# flightcheck v0.6.0

Released: 2026-08-03 · Tagged: 2026-08-04

## Why this tag is dated a day after its release

`v0.6.0` points at `da254e3`, the commit that was built and served to the
public on 2026-08-03. The tag was created the following day.

This repo has said in four places that "a tag invented after the fact is a
decoration, not a release rhythm", and refused to tag v0.3 and v0.4
retroactively on exactly that ground. Cutting this tag looks, on its face, like
the same thing. It is not, and the distinction is now written down as
DECISIONS 032: **a tag may be cut after the fact at the commit that was actually
deployed, and may not be invented for a boundary that never shipped
separately.** v0.3 and v0.4 had no separable deployed commit — they were folded
into v0.5 because there was nothing distinct to point at. This release has one,
and the boundary already exists in the deployment record. The tag names it; it
does not invent it.

Two consequences of tagging the deployed commit rather than a tidier one, both
stated here rather than left for a reader to find:

- **The version manifests at this commit read `0.5.0`.** `da254e3` was not going
  to be edited to make a version string agree with a tag applied afterwards.
- **No eval gate ran at this commit.** See Measured evals below. This is the
  sharper of the two.

## What shipped

The release where the operator can be away for a week.

- **You can leave, and take nothing with you.** Account deletion is self-serve
  from settings and immediate — every recording, transcript, report, package and
  order. Recordings go before database rows and a storage failure aborts the run
  before anything is removed, so a failure means *nothing* was deleted and you
  try again rather than being stranded half-deleted (DECISIONS 025). The
  operator purge script and the endpoint run the same code instead of two
  implementations free to drift. You can also change the email you sign in
  with, with the confirmation round trip stated honestly.
- **A landing page a stranger actually reads.** Rebuilt to the screen parity the
  market ships: a four-step how-it-works, itemized pricing, and answers to the
  questions people ask before paying. What unlocks for $49 is listed *before* the
  button, with the refund line beside it. (The design pass cut this down again a
  day later — the on-page FAQ moved to `/faq`. See v0.7.0.)
- **The operator gets instruments instead of hand-written queries.**
  `GET /api/metrics/usage` and a report generator that enforces the honesty rules
  in code rather than trusting whoever runs it: every rate prints its counts, the
  account count leads the summary, a one-account sample is labelled a self-test
  in the output, and a metric the product does not instrument prints as **not
  instrumented** with its reason rather than as a dash the reader is free to
  interpret. Also a dead-letter record for permanently failed jobs — failures
  were previously discovered by customer complaint — and backup, restore and
  token rotation written down as procedures.
- **The pipeline survives its own history** (DECISIONS 034). Backoff on every
  model call site: the audit that opened this work found one of seven covered,
  and a discovery-based test then found **eleven** call sites rather than seven
  and pinned the count so a twelfth cannot ship without failing the gate. A
  scoring concurrency limit and memory guard, behind a measured ~1.6GB peak and
  an out-of-memory kill that had already happened once in production. An overall
  job deadline, so one job cannot hold a worker for fifty minutes by chaining
  individually-reasonable timeouts.
- **Security and observability.** A CSP with an explicit `connect-src`
  allowlist, `frame-ancestors 'none'`, and a Permissions-Policy granting the
  microphone on the interview room and nowhere else (DECISIONS 026).
  Capability revocation end to end, with automatic expiry deliberately not
  minted yet and DECISIONS 029 saying why rather than implying a window that
  does not exist. Prompt-injection refusal with its own eval suite, whose benign
  false-positive baseline is **zero** because the first classifier refused real
  prompt-engineering job postings — the product's core input (DECISIONS 027).
  `/healthz` now probes the database and answers 503 naming what failed; it
  previously returned an unconditional true, which is what let a dead build keep
  serving while every deploy failed. One request id from the browser through the
  web routes into the worker's logs and back on the response. Error monitoring on
  both runtimes, with the boundary drawn around what a third party receives —
  identifiers and stack traces, never a recording, transcript or report body
  (DECISIONS 033).
- **One live session per package.** Two tabs on one session both minted upload
  URLs and the second overwrote the first — an interview lost with no error
  anywhere. The refusal now says so, and says no session is consumed
  (DECISIONS 028, which also records what this costs a crashed tab).

Full detail: `CHANGELOG.md`, `[0.6.0]`.

## Measured evals (release gate: `scorer-evals`)

**No gate ran at this commit, and one was required.** `evals/reports/` held
nothing between `2026-08-03-v05-gate.md` and the run made for these two tags on
2026-08-04. `CLAUDE.md` non-negotiable 3 requires the suites to pass "before any
tag" and nothing was tagged, so the letter of that rule held — but
`docs/deploy.md` puts the gate in the pre-deploy checklist, and this release was
deployed anyway.

The run of record for this tag is therefore the one made on the `v0.7.0` tree:
`evals/reports/2026-08-04-v06-v07-gate.md`. **It is a single run covering both
tags**, stated in words so two tags do not imply two runs. All three suites
passed, exit 0. Nothing can make a gate have run at `da254e3` after the fact and
this document does not pretend otherwise.

`docs/deploy.md` §5.2 has been amended so a deploy and its gate cannot come apart
again — the runbook previously had no step that wrote release notes or published
a release, which is the same hole.

## Known limits

Carried forward from [v0.5](v0.5.md#known-limits), all still true, plus:

- **Zero external users and zero external paying customers.** The one $49 order
  on the books is the operator's own, self-refunded after proving the path end to
  end. Every rate this release can now measure is therefore unmeasured for want
  of a sample, not for want of an instrument — a materially better position than
  the previous documents claimed for themselves, and still not usage data.
- **The eval sample is small enough that one case decides two of three suites**:
  N=3 triplets at layer 1, 2 at layer 3. The injection suite is the first with a
  sample worth the name, at 29 fixtures.
- **A customer whose tab crashes mid-session waits out the hard cut.** One live
  session per package has no release valve other than the 25-minute limit. No
  session is consumed, so the cost is time rather than entitlement. The fix is a
  room heartbeat and it is the next batch's work.
- **Automatic capability expiry is not minted**, only revocation. DECISIONS 029
  records why, and it depends on the same heartbeat.
