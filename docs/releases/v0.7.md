# flightcheck v0.7.0

Released: 2026-08-04

The design pass — and the release audit that found the product had shipped
twice while its documents stood still.

This tag sits on the design pass **plus** the audit fixes that release required,
and it was cut only after that commit was deployed and read in production —
which is the order DECISIONS 032's rule requires, since it puts a tag on the
commit that was actually deployed. `v0.6.0` is the same rule applied backwards,
to a commit that had already shipped.

## What shipped

**One design system, and it is enforced rather than described** (DECISIONS 035).
Every colour, type step, radius and shadow is declared once in
`app/globals.css` and composed in `lib/ui.ts`; a test walks `app/`,
`components/` and `lib/` and fails on a raw palette utility, an arbitrary
colour, a pixel font size, a CSS gradient, a hand-rolled page column, or a dash
in a sentence a reader sees. The previous version of that rule was written down,
believed, and scanned exactly one directory — the argument for enforcement is the
batch's own measurement: all eight files that scan covered had zero raw colour
literals, while a hundred and eight source files had no scan at all and
forty-five of them had accumulated about six hundred between them.

**Light only.** The product shipped `dark:` variants throughout, so it rendered
as a different product depending on the reader's operating system setting.

**The report says why a verdict is what it is.** 4.27 out of 5 next to the word
"Approaching" reads as a bug until you know the rule has two clauses. One gauge
now draws both — overall against the 4.0 Ready bar, and the weakest dimension
against the 3.0 floor — with a sentence naming the one that decided it. The
verdict is deliberately not a traffic light; rendering "Not yet ready" in red
would punish the reader this product exists for.

**The system was built twice**, and that is in the record rather than smoothed
over. The first pass was built from a prose description of the design reference
and shipped a 110% root, a serif display face and ~56px pill controls. Put side
by side with the reference it was wrong in four named ways, and the second pass
rebuilt it from the reference's **measured computed styles**. A prose
description of a design is a lossy encoding of it, and the loss is invisible
until someone sees both.

**Then two rounds of adversarial review**, because the first round's fixes are
the thing most likely to be wrong. Round 2 read the fixed tree with different
reviewers and found 41 findings, 7 HIGH — including a blank page for readers
with Reduce Motion enabled, where the accommodation built for that reader was
what blanked the page for them.

**And the one nothing in this repo could have caught by reading its own source.**
`/rubric` shipped to production reading *"an overall of 4.0single dimension below
3.0"*. The source was correct, the unit test printed the correct string, and
1,740 tests passed: a module-scope constant assembled by `+`-concatenating
template literals gets constant-folded at build time, and the fold drops the
literal text after the last interpolation. A second instance had corrupted the
readiness gauge's screen-reader sentence. It was found by opening the deployed
page and reading it, and the gate that now catches it reads the built output
rather than the source.

Full detail: `CHANGELOG.md`, `[0.7.0]`.

## What this release also contains: a full release audit, and what it found

This tag carries the fixes from a full release audit run on 2026-08-04 — a
parallel auditor per criterion, plus an independent confidentiality and secrets
sweep held deliberately apart from them. Most of the standards this repo holds
itself to came back failing, worse than the equivalent pass before v0.5, and the
diagnosis was one sentence: two batches shipped and the documents did not move. Most failures were a sentence that was true when written, pointed at
the future, and turned false by v0.6 shipping — "the adversarial eval suite is
scheduled for the next release", "F-13 will instrument this in v0.6",
"self-serve deletion arrives in v0.6". All three had shipped.

Two findings are worth naming here rather than leaving in a scoreboard:

- **An orphaned `demo.gif` was still being served from production.** Referenced
  by nothing, deleted from the README a day earlier, and still reachable at its
  URL — rendering, in pixels, a passage that had been removed from the sample
  report the day before because of how it read, under a caption asserting an
  anonymization this repo's own runbook forbids claiming. The fixture had been
  cleaned; the image showing the fixture had not. Deleted.
- **Three of the four honesty rules v0.6 advertised were not enforced.** An
  auditor broke each one and watched the test suite stay green. The sharpest:
  `assert NOT_INSTRUMENTED_NOTE in usage.notes` compared a constant against
  itself, so it held for any value including the empty string — the report could
  have printed "not instrumented" with no reason at all and nothing would have
  failed.

`RETRO.md` carries the rest.

## Known limits

Carried forward from [v0.6](v0.6.md#known-limits), all still true, plus:

- **N=3 and N=2 are not precision estimates.** One boundary case decides two of
  the three suites. Growing the golden set stays queued.
- **True phone rendering is unverified.** Chrome's minimum window width blocked
  it at every attempt; everything narrow in this batch was computed from the
  built CSS and the component tree rather than seen.
- **`prefers-reduced-motion` has not been watched working with the OS setting
  on.** The blank-page defect was demonstrated from the built server HTML plus
  React's documented hydration behaviour and fixed with a CSS backstop that
  depends on neither — but nobody has toggled it by hand.
- **The live interview room has never been opened.** Its pre-connect state is
  verified in production; the clock, mic meter and transcript of a running
  session cost a session slot and a realtime call to see, and have not been.
- **There is no demo recording.** The README carries two stills of the running
  app. A recording needs a live twenty-minute session and waits for v1.0. It is
  not being promised in a caption again — the last two README failures were both
  introduced by a caption promising a future artifact.
