# flightcheck v0.2.0

Released: 2026-08-01

## What changed

v0.2 is the interviewer-UX release. Every item traces to the first full
end-to-end session (2026-07-29 — run by the developer as the product's first
user; N=1, no external users yet), which surfaced the gap between "asks good
questions" and "feels like a real interviewer":

- **The interviewer opens the call.** A hello with an audio check ("can you
  hear me okay?"), one conversational sentence of framing, a put-at-ease
  line — then the first question, asked naturally. No more mutual silence at
  the start, no "Question 1" read aloud, no reciting the job description.
  The structural fix mattered as much as the script: server-VAD realtime
  models never speak unprompted, so the client now triggers the first
  response at data-channel open — instructions alone were measured to
  produce a minute of silence.
- **Thinking pauses are respected.** Mid-answer pauses are treated as
  thinking, not end-of-answer: the interviewer waits, or offers one short
  supportive scaffold; it never re-asks the same question verbatim and never
  advances over an unfinished answer. Our users are non-native English
  speakers — pauses are the norm, and this behavior decides whether the
  product feels like a coach or an interrogation.
- **Active listening.** One-sentence restatements before follow-ups;
  evidence probes framed with an acknowledging clause instead of a bare
  "what was the number?".
- **The clock is managed out loud.** The model has no clock, so the client
  injects `[time status]` notes at 75% elapsed and at the wrap-up margin;
  the interviewer steers toward a closing arc without ever mentioning the
  notes. (Injection is unit-tested; the felt wrap-up arc lands only in
  sessions that run past the 15-minute mark.)
- **The report explains itself.** Per-dimension cards now show the judge's
  written rationale — computed since v0.1 but never rendered — with the
  candidate's own verified words as quotes. Displays are trimmed to the
  load-bearing few (four quotes per dimension, five timeline observations,
  DSP conflicts always surfaced) with the full sets one disclosure away.
- **Honest failure copy.** A briefly unreachable scoring worker now shows an
  auto-retrying "can't reach the scoring service" page instead of being
  indistinguishable from a wrong link.
- **Scoring survives pressure.** The content judge backs off briefly
  (1s/2s/4s) on transient 429/transport errors — sized for concurrent
  sessions — instead of failing a non-repeatable 20-minute interview.

## Measured evals (release gate: `scorer-evals`)

| Suite | Metric | Result | Baseline | Run date |
| --- | --- | --- | --- | --- |
| Layer 1 — rubric discrimination | blind-rank accuracy | 1.0 | 0.8 | 2026-08-01 |
| Layer 3 — delivery discrimination | judge accuracy | 1.0 | 0.8 | 2026-08-01 |

**Stated plainly: the gate flickered during this release window, and we are
publishing that.** Five runs were made on 2026-08-01: the v0.1 tree passed
twice, the v0.2 tree failed twice (identical signature: one triplet's
borderline answer saturating to 5.0, tying strong) and then passed. A
controlled probe — re-running the untouched v0.1.0 code in the same window —
passed while the v0.2 tree was failing, and a code-path analysis shows the
v0.2 changes cannot alter successful judge calls (the backoff wrapper is
call-for-call identical on success; the interviewer-instruction changes are
outside the judged path). Conclusion: judge-side nondeterminism on a
boundary triplet, not a code regression — the exact saturation failure mode
the v0.1 judge redesign fixed, re-emerging intermittently at N=3. Full run
record: [`evals/reports/2026-08-01-v02-gate.md`](../../evals/reports/2026-08-01-v02-gate.md).

Consequence, not excuse: **growing the golden set (E1) moves up the
roadmap** — with N=3, one boundary triplet decides the gate, which is too
fragile to keep trusting. The v0.1 release note called N=3 "a
mechanism-level signal, not a large-sample accuracy claim"; v0.2 measured
exactly why.

## Known limits

- Everything in the [v0.1 known limits](v0.1.md#known-limits) still applies
  except the report's missing rationale (fixed this release).
- The interviewer's new behaviors are instruction-shaped, not guaranteed:
  they were confirmed by feel in real sessions (opening, pause tolerance,
  restatement), but consistency across sessions is not yet measured.
- Sessions shorter than the time-status checkpoints (15:00 / 18:00) never
  exercise the closing arc.
- Very short sessions are still scored like full ones; "insufficient
  evidence" handling (skip scoring, say so honestly) is designed and queued.
- **Zero external users so far.** Every session to date was run by the
  developer; the real-usage metrics promised for v0.2 slipped with the
  payments timeline (`docs/metrics/`, DECISIONS #008) and land with the
  first external pilot. No usage numbers are claimed anywhere in this repo.
