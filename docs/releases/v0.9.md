# flightcheck v0.9.0

Released: 2026-08-05

The product learned some manners.

A package now says whose interview it is, everywhere it is named. The LinkedIn
upload shows where its PDF comes from instead of telling. And the top-bar menus
close the way every menu a customer has ever used closes.

## What shipped

**Every surface that names a package now says which company** (F-56, DECISIONS
038). The employer identity that landed on the /packages card in F-54 — the
favicon when the pasted JD URL is the employer's own site, the company name
always, nothing at all when the JD never named one — now follows the package to
the top-bar switcher and its rows, /home, /sessions, /progress, /rubric, and
/checkout. Two packages for the same role stop being indistinguishable, which
was the whole complaint: the operator's own screen showed "Forward Deployed
Product Manager" twice with nothing to tell them apart.

One component decides. The rule lives in a single decision module, a wiring
test forbids any page from re-deriving it, and /rubric's hand-written company
line from two days ago is gone into it — that line was the first symptom of
the disease this component exists to prevent. The honesty rule is unchanged
and enforced by the same code path: no company, nothing rendered, never a
placeholder square.

**The "?" beside the LinkedIn upload shows, not tells** (F-55, DECISIONS 039).
The one-line hint stays; the new trigger opens a speech-bubble walkthrough in
three steps — an animated mock of your profile page clicking "More", the menu
opening and "Save to PDF" being clicked, the file arriving where the upload
is. Step counter, Back and Next, a replay per step; Next relabels to Done on
the last step so the footer never reflows; Done closes the bubble and focuses
the real file input.

The mock is drawn entirely in the product's own palette and names LinkedIn's
labels as text. No screenshots of another company's interface: they would sit
in a public MIT repository, carry someone else's trade dress, and go stale the
next time that menu moves. The interaction grammar came from three researched
references — driver.js for the footer, Shepherd.js for the beak and focus
return, Nielsen Norman Group for one action per step — and the animation obeys
the motion budget: one-shot on step entry, transform and opacity only, and
under reduced motion the finished picture plus the caption, losing nothing.

**The top-bar menus dismiss like menus** (F-57, DECISIONS 038). Click anywhere
else and they close; Escape closes and returns focus to the trigger; opening
one closes the other. They were native details elements, which only ever
closed from their own button. The fix is a small client wrapper that renders
the same server-renderable structure, so with JavaScript disabled the menus
degrade to exactly the old click-to-toggle behavior — the failure mode is the
status quo. One caveat is documented rather than hidden: two menus opened
purely by keyboard can coexist until Escape or a pointer arrives, which
matches the old baseline, where nothing closed them at all.

## What the review caught

The batch ran as fourteen delegated agents — a research trio, a spec author,
foundations, three implementation tracks in isolated worktrees, and two
adversarial review rounds — with the human controller integrating. Three
findings survived to be worth publishing.

**A chip that could not shrink.** The identity chip lacked `min-w-0`, so a
long company name on a narrow screen would overflow the line instead of
truncating. Both review rounds confirmed it independently, and both routed it
to the merge rather than fixing it, because the file belonged to the
foundations layer and their zone lists said no — the discipline held under
temptation, which is what it is for. The controller applied the one-word fix
at integration.

**A baseline that moved four pixels.** In dropdown rows that carry a favicon,
the flex group's exported baseline became the image's bottom edge, sinking the
session count below the title. The reviewer measured it, fixed it with
`items-center`, and wrote the failing test first.

**A hit target that was 21 pixels at the root this product actually uses.**
The walkthrough's close glyph met the spec's 24px minimum only at a 16px root;
this product's root is 14px. Fixed with the footprint unchanged, pinned by a
test that bans the old size from returning.
