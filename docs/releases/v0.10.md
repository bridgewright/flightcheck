# flightcheck v0.10.0

Released: 2026-08-05

The judge speaks for itself, and the product stopped standing still.

## What shipped

**The report's emphasis is the judge's own** (F-48, DECISIONS 043). Since the
design pass, each dimension rationale emphasised its first sentence, by
position, because the product refused to decide which of a judge's words
matter. Now the judge marks the clause itself, verbatim from the rationale it
wrote, and the contract is enforced in code twice: the content path resolves a
whitespace-normalized match back to the exact character-for-character slice,
and the report compiler drops any span that is not an exact substring of its
own rationale, for every channel. A fabricated emphasis is worse than none in
a product whose claim is that its verdicts are arguable. Screen, PDF and
markdown emphasise the same span through one shared rule; reports written
before the field existed render exactly as they always have.

**Strengths and weaknesses are the judge's words now** (F-03b, closing
DECISIONS 016's deferral). The per-dimension fields that shipped empty are
authored by the content judge in the same call that scores, take the same
language lint as every other sentence the report ships, and render
conditionally in all three formats, so an old report shows no empty section
headers. The delivery judge is not yet instructed for these fields, so
anything it volunteers there is dropped at compile rather than risking a
failed scoring run on prose nobody contracted. The deterministic headline
stays deterministic.

**The signed-in product animates its own data** (F-58, DECISIONS 041). The
report's overall score counts to its value once on first view; the readiness
gauge sweeps to its reading, after a refactor off width/left styling that
made the sweep legal at all; progress cards, session rows and the journey
strip enter with the landing's one-shot vocabulary; a status that flips under
a poll tick fades in instead of teleporting. The press-scale the design spec
once granted is now formally declined instead of silently absent.

**A Feedback door in the footer** (F-59, DECISIONS 040): a labeled mailto
beside the support address, subject prefilled, no new place customer data
lives.

**The product introduces itself to machines** (F-60, DECISIONS 042).
`/llms.txt` states what the product is, costs, and is not, every number
imported from the constants the pages render. robots.txt names seven AI
crawlers and allows them on purpose, with `/p/` capability links disallowed
for every agent. Product and FAQPage structured data ship from the same data
modules the visible pages render, so they cannot drift. No invented ratings.

**Average response latency joined the progress table** (F-23). The scorer had
computed it since the schema existed; the trends table now shows it with the
report page's exact label and format, and a dash where a session has no
measurement.

## The gate failed first, and that is the process working

This tag changed the content judge for the first time since the eval gate has
existed, and the gate's first run FAILED: the triplet suite scored a
borderline answer level with a strong one, 4.7 to 4.7, on a triplet that
passed cleanly before the judge learned to author strengths. The mechanism
read straight out of the new rules: mandating 1-3 strengths per dimension put
the judge in a positive-finding frame while it scored. The fix states that
the anchor score is fixed before the authored fields are written and cannot
be moved by them, and lets both lists be empty so nothing is invented for
weak answers. The second run passed 3/3 with the other two suites unchanged.
Full detail: `evals/reports/2026-08-05-v010-gate.md`.

## What the reviews caught

Fourteen agents built the UI half and seven built the judge half, each with
two adversarial review rounds. Worth publishing: the review that routed the
delivery-judge risk to the merge (the shared schema advertises fields the
delivery prompt never instructs, and a volunteered inner-state item would
have failed a real customer's non-repeatable scoring run through the lint);
the round-2 reviewer that treated a clean round-1 verdict as the suspect and
re-derived the gauge geometry mark by mark; and a round-2 fix from the
previous batch (a hydration mismatch in the gauge sweep's reduced-motion
branch) that the controller had missed at merge and this batch's housekeeping
caught by checking `git cherry` instead of trusting the merge log.
